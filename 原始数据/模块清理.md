## shutdown 应该遵守的三个原则

### 1. 最佳努力：一个失败不能阻止其他独立清理

不要这样：

```
def shutdown(self):
    self.fs_tier.shutdown()       # 抛异常
    self.obj_tier.shutdown()      # 永远不会执行
    self.primary.shutdown()       # 永远不会执行
```

应该收集错误并尽量继续：

```
def shutdown(self) -> None:
    errors = []

    for tier in reversed(self.secondary_tiers):
        try:
            tier.shutdown()
        except Exception as exc:
            errors.append(exc)

    try:
        self.primary_tier.shutdown()
    except Exception as exc:
        errors.append(exc)

    if errors:
        raise ExceptionGroup("Tiering shutdown failed", errors)
```

但这只适用于彼此独立，或者即使前一步失败，后一步仍然安全的资源。

### 2. 尊重依赖关系：不能盲目“继续清理”

tiering 中应当先阻止新工作，再等待 I/O 停止，然后释放底层内存：

```
RUNNING
   ↓ 禁止新 submit
CLOSING
   ↓ drain secondary jobs
I/O_STOPPED
   ↓ 关闭 secondary tiers
   ↓ 释放 primary memoryview / mmap
CLOSED
```

如果 `drain_jobs()` 或停止线程失败，则不能确定 secondary 已经停止访问 primary memory。这时不能为了“清理彻底”而继续释放 mmap。

也就是说：

```
try:
    stop_and_drain_secondaries()
except Exception:
    # primary memory 必须暂时保留
    # 否则可能造成更严重的内存安全问题
    report_incomplete_shutdown()
    return
```

资源泄漏通常比释放仍在使用的内存更安全。

### 3. shutdown 应该幂等

调用两次不应造成新的错误：

```
manager.shutdown()
manager.shutdown()  # 应该安全
```

可以有明确状态：

```
class Lifecycle(Enum):
    RUNNING = auto()
    CLOSING = auto()
    CLOSED = auto()
    CLOSE_FAILED = auto()
```

入口先封闭：

```
def shutdown(self) -> None:
    if self._state is Lifecycle.CLOSED:
        return
    if self._state is Lifecycle.CLOSING:
        return

    self._state = Lifecycle.CLOSING
    ...
```

但 `CLOSE_FAILED` 要记录“哪一步已经完成”，否则重试时可能重复关闭已经释放的资源。

## 失败以后怎么办

不能统一回答“重试”或“忽略”，要根据资源分类决定。

|失败资源|通常策略|
|---|---|
|telemetry、临时文件|记录 warning，继续|
|文件描述符关闭|记录错误，继续清理其他独立资源|
|网络连接关闭|尽力关闭；多数情况下可继续|
|worker/thread 停止|不能释放它仍可能访问的内存|
|in-flight I/O drain|保留相关 buffer/mmap，报告关闭不完整|
|memoryview release|记录错误；不要假装已经完全关闭|
|mmap cleanup|保持失败状态，允许上层报告或有限重试|

shutdown 的结果最好不要只有“抛异常/不抛异常”两个信息，而是能表达：

```
@dataclass
class ShutdownResult:
    fully_closed: bool
    errors: list[BaseException]
    leaked_resources: list[str]
```

不过在 Python 项目里，更常见的是：

- 正常关闭：返回；
- 可忽略的问题：记日志；
- 关闭不完整且影响安全：抛出聚合异常；
- 对象状态保留为 `CLOSE_FAILED`。
