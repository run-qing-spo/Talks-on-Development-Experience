## 怎么找名词

不要试图在编码前一次想全。最实用的方法是：**先写一段不带类名和函数名的系统故事，然后圈名词、动词和状态词。**

以 promotion 为例：

> 调度器收到一个请求，使用 block key 查询 primary。primary 没有数据，于是查询 secondary。secondary 命中后，primary 为该 block 预留一个槽位。多个待传输 block 被合并成一个 job。job 完成后，primary 将这些 block 发布为可用。

从中提取：

| 语句成分 | 候选概念                                         |
| ---- | -------------------------------------------- |
| 名词   | request、block、key、primary、secondary、slot、job |
| 动词   | lookup、reserve、batch、submit、complete、publish |
| 状态词  | absent、in-flight、ready、failed                |

但并非每个名词都需要变成数据结构。接下来用几个问题筛选。

### 1. 它需要独立身份吗？

问：“我们以后是否需要单独指出它？”

- “哪个 block？”→ `OffloadKey`
- “哪个请求？”→ `req_id`
- “哪次传输？”→ `job_id`
- “哪一个槽位？”→ `block_id`

如果两个东西有不同的身份，就不要因为当前恰好一一对应而合并。例如 job 和 block 必须分开，因为一个 job 可以包含多个 block。

### 2. 它有独立生命周期吗？

问：“它何时创建，何时消失？”

```
request：请求开始 → 请求结束
job：创建 → 提交 → 完成
block：写入 → 可用 → 淘汰
slot：分配 → 占用 → 释放
```

生命周期不同，通常就应该是不同概念。尤其要警惕：

> A 已经结束，但 B 仍然存在。

当前模块里，请求可能已经结束，但异步 job 仍在执行。因此 job 不能依附于 request 对象才能存活。

### 3. 它有自己的状态吗？

如果一个东西会独立改变状态，通常值得单独建模：

```
job:   CREATED → SUBMITTED → FINISHED
block: ABSENT → IN_FLIGHT → READY
slot:  FREE → RESERVED → OCCUPIED
```

虽然 block 和 slot 经常一起变化，但并不相同：

- block 是逻辑内容；
- slot 是承载内容的物理资源；
- 传输失败后，block 可以变为 `ABSENT`，slot 则回到 `FREE`。

### 4. 它有所有者吗？

对每个候选名词填写一句：

> 谁创建它？谁能修改它？谁负责销毁或释放它？

答不出来通常说明设计还没有闭环。

例如：

|对象|创建/分配者|使用者|释放者|
|---|---|---|---|
|primary slot|primary manager|transfer job|primary manager|
|job|tiering manager|secondary tier|tiering manager收到完成通知后|
|FS task|FS tier|worker thread|thread pool|
|request context|scheduler|各 tier|请求生命周期管理者|

尤其危险的是：“大家都能创建，但没人明确负责释放”。

### 5. 它只是字段，还是一等概念？
判断时可以问：

> 开发者是否需要反复记住“操作 A 时，必须同时用相同方式操作 B”？

最简单的判断口诀是：

> **必须一起创建、一起移动、一起过滤、一起保持对应的字段，应该优先考虑封装成一个概念。**

主要是让错误的状态更难表示

# 开始设计功能时，先填下面这些，不要求一次写全：
1. 系统故事：
   谁为了什么，从哪里把什么移动到哪里？

2. 核心名词：
   请求：
   逻辑数据：
   物理资源：
   异步操作：
   管理组件：

3. 身份：
   每个东西靠什么被唯一指出？

4. 生命周期：
   谁创建？
   何时可用？
   谁释放？
   失败时谁清理？

5. 状态：
   初始状态？
   成功状态？
   中间状态？
   失败回到哪里？
   
在 tiering promotion 中，答案很短：

```
逻辑数据：block，以 OffloadKey 标识
物理资源：primary slot，以 block_id 标识
异步操作：transfer job，以 job_id 标识
管理组件：tiering manager / primary manager / secondary tier

block：ABSENT → IN_FLIGHT → READY
slot：FREE → RESERVED → OCCUPIED
job：CREATED → SUBMITTED → FINISHED
```
