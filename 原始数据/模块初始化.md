## 初始化设计的五个问题
```
组件：
依赖什么：
创建什么资源：
何时算 READY：
初始化失败谁清理：
正常关闭谁清理：
```

例如 FS tier：

```
组件：FileSystemTierManager
依赖：primary_kv_view、block size、存储目录配置
创建：文件映射器、异步 lookup manager、线程池
READY：目录可用，线程池已启动，可以接受 submit
失败清理：构造它的装配层
正常关闭：自身 shutdown()
```

这里有一条重要规则：

> 创建资源的人，要么拥有它并负责关闭；要么立即把所有权明确移交给另一个对象。

否则很容易出现 mmap 是 spec 创建的、primary 使用、manager 关闭，最后谁负责释放却不明确的情况。


## `__init__` 应该做到什么程度

`__init__` 最适合做：

- 保存依赖；
- 建立内部不变量；
- 创建便宜且不容易失败的对象；
- 让构造完成的对象立即可用。

对于可能昂贵或容易失败的操作，例如：

- 启动很多线程；
- 连接远程存储；
- 打开文件；
- 分配大量内存；
- 注册外部资源；

## 显式工厂：

```
class TieringManager:
    @classmethod
    def create(cls, config):
        validated = validate(config)
        resources = allocate(validated)
        return assemble(resources)
```

工厂的价值不是形式，而是它可以负责“事务式初始化”：

```
created = []
try:
    primary = create_primary()
    created.append(primary)

    secondary = create_secondary(primary)
    created.append(secondary)

    return create_manager(primary, secondary)
except Exception:
    for component in reversed(created):
        component.shutdown()
    raise
```

要做到：

> 要么完整初始化并返回一个 `READY` 对象，要么清理已创建资源后失败；不要返回半初始化对象。
